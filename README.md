# Everpath — WoW Forever Companion

**Status:** Public development repository · v1.5 · Not an official Blizzard product.

Everpath is an independent, community-focused companion web app for World of Warcraft Forever. It focuses on a low-friction experience for **Professions & Crafting** and **Companion Pets**, with selectable Alliance and Horde themes. Its acquisition explorer and map framework are under development.

## Current features

- Profession browsing, recipe/material exploration, and crafting shopping lists
- Companion pet discovery and collection management
- A source-review framework for gathering, vendor, drop, quest, and pet acquisition locations
- Blizzard game-data imports using local developer credentials (credentials are never shipped to the browser)
- Responsive UI with compact pet cards and faction themes

## ForeverDB data attribution

**Provider approval is pending.** The footer contains a visible ForeverDB attribution badge with a pending-integration label. Source-specific credit appears for reviewed ForeverDB records; see [integration requirements](docs/FOREVERDB_INTEGRATION.md) for rate limits, provenance, endpoints and review steps.


We plan to integrate the [ForeverDB](https://foreverdb.net/) API as an **attributed third-party data source** for acquisition and gathering information, subject to approval and the provider's usage requirements. Wherever ForeverDB data is displayed, the app should prominently provide a link back to ForeverDB and retain source attribution. **No ForeverDB data is included in this public repository.**

## Security and data

- `.env` and local import caches are ignored by Git.
- The committed `.env.example` contains only blank placeholders; do not add credentials to it.
- Real Blizzard data is generated by local import tools. The checked-in JSON files are scaffolding/examples unless explicitly validated.
- Do not publish Blizzard Client Secret, ForeverDB API keys, OAuth tokens, or local cache files.

## Local setup

```powershell
npm install
Copy-Item .env.example .env
# Edit .env locally and enter credentials only when running API import tools.
npm run dev
```

Production build: `npm run build`. Tests: `npm run test`.

This release continues v1.3 without replacing verified Blizzard data. No Supabase required.

- **Compact pet cards:** smaller and tighter responsive grid; 56-pixel source icons are no longer stretched.

### Data source / map requirements

The shipped `src/data/acquisition.json` is **intentionally empty** because no Forever location evidence + license clearance has been imported. The site must **not** display unverified acquisition methods or coordinates as game facts.

Use this normalized schema when sourcing data:

```json
{
  "schemaVersion": 1,
  "gameVersion": "forever",
  "updatedAt": "2026-11-10",
  "records": [
    {
      "id": "unique-reviewed-record-id",
      "entityType": "item",
      "entityId": 123,
      "method": "gathering",
      "description": "Specific source details with independent evidence",
      "sourceTitle": "Published, reviewable reference",
      "sourceUrl": "https://example.com/source",
      "license": "Rights/permission actually confirmed",
      "reviewedAt": "2026-11-10",
      "location": {"zoneName": "Verified zone"}
    }
  ],
  "maps": []
}
```

**The record above is documentation only; item 123, the example URL and zone are NOT real game data and MUST NOT be pasted into the published catalog.**

For map pins also define a map in `maps` with `{id, zoneName, imagePath:'/assets/maps/zone-image.png', width, height}` and supply `location:{zoneName,mapId,x,y}` with normalized x/y in 0–100 and a *verified* pixel-to-coordinate transform. Map artwork belongs under `public/assets/maps/`, only with permission to redistribute. The map uses Leaflet's `CRS.Simple` and `ImageOverlay`, not Earth coordinates.

GatherLite is a promising **candidate source** but contains WoW Classic/Forever addon data and third-party map/terrain assets whose rights and version need independent verification. A repository being publicly readable does not automatically allow republishing its bundled data. There is **no automatic GatherLite scraping** in v1.4 and **no proven pet acquisition dataset** included. The next data milestone is licensing review and a small, verified source import.

### Build limitations

Automated Node tests run without external services. A full `npm install` and Vite build must be run locally to confirm the new Leaflet dependency. Blizzard imports are private to your machine; the shipped catalog files are empty placeholders.

# v1.5 — Acquisition Source Staging & Evidence Review

This version **does not claim map pins or material/pet sources have already been imported**. The Blizzard identity/recipe/media catalog remains the authoritative primary ID source. `src/data/acquisition.json` intentionally starts empty. The acquisition explorer now offers appropriately labeled external research links while there are no approved source records.

## Why ForeverDB?

[ForeverDB Developer API](https://foreverdb.net/developers) publishes documented gathering summaries, vendor/quest data and recipes. It requires a developer key and visible attribution. The provider specifies **60 requests/minute, 10,000/day**, and states that some gathering spawn counts are Classic-derived rather than Forever-verified. The API is separate from Blizzard and **not bundled** in Everpath.

[GatherLite](https://github.com/Wuild/GatherLite) remains an optional coordinate-data candidate, but its bundled ground-route/terrain components are GPL-3.0-or-later and map artwork needs separate rights review. **Do not copy its data or map imagery into `public/` without a license/version audit.**

## 1. Optional authorized staging import

Request a key directly from ForeverDB, agree to the attribution rules, then add the following **only** to `.env` (never `VITE_`):

```dotenv
FOREVERDB_API_KEY=your_authorized_key
```

Then run:

```powershell
npm run api:foreverdb:stage
```

This fetches `/api/v1/meta`, gathering summaries for herbalism/mining/skinning/fishing, and the first page of zones, with retry for HTTP 429/5xx and timeouts. It writes to `imports/staging/foreverdb/` (ignored by Git). **Nothing in staging appears on the website.** No other credentials are sent to the provider. The result schema is saved raw; there is no unverified mapping from human-readable zone names to Blizzard item/pet IDs.

The import is deliberately **a small metadata/staging pass, not an exhaustive source import**. Gathering is source coverage, not a set of guaranteed world-map spawn pins. Future paginated, incremental source import must use approved provider access and obey its limits.

## 2. Manual provenance and rights review

Review the staged JSON and compare each candidate to Blizzard imported item/pet IDs and independent Forever evidence. Create `imports/reviewed-sources.json` (a gitignored local file):

```json
{
  "records": [
    {
      "approved": true,
      "id": "reviewed-unique-id",
      "entityType": "item",
      "entityId": 123,
      "method": "gathering",
      "description": "Human-reviewed acquisition note",
      "sourceTitle": "Approved and traceable source",
      "sourceUrl": "https://example.org/source",
      "license": "Exact license/permission confirmed during review",
      "reviewedAt": "2026-11-10",
      "evidenceLevel": "classic-reference",
      "location": {"zoneName": "Human-verified zone name"}
    }
  ]
}
```

**This is only a schema illustration, not authentic item 123/source/zone data.** The reviewed `approved` flag is an explicit human decision, not inferred from the raw import. Never publish unlicensed copied text or coordinates. For provider data, credit ForeverDB visibly and retain its source URL.

```powershell
npm run data:review-sources
npm run data:validate-acquisition
```

The review tool merges by record ID, validates required evidence and coordinate bounds, and writes to `src/data/acquisition.json`. Every source is labeled in the UI:

- `forever-verified`: specifically observed/validated in Forever.
- `community-report`: reported by players; verify in game.
- `classic-reference`: historical hint only, NOT confirmed in Forever. Cannot be published as exact Forever pins.

**Map support:** Leaflet `CRS.Simple` remains dormant until licensed map art and transformed coordinates are reviewed. A zone name alone cannot produce a credible marker. Pet sources are not available from the provider's documented API; pet-specific data requires a separate, rights-cleared source and manual mapping.
